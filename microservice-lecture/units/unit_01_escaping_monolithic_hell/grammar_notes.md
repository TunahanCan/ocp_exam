# Ünite 1 · Escaping monolithic hell — Grammar Notes

**Amaç:** Kaynak kitabın 1–32. sayfalarındaki cümleleri yalnızca kelime kelime değil, anlam ilişkilerini görerek okumak. Bu kaynak, [çift dilli ana dersin](bilingual_notes.md) dilbilgisi eşlikçisidir. Teknik kelimeler için [ünite sözlüğünü](vocabulary.md) kullanın. [Grammar PDF](grammar_notes.pdf)

Aşağıdaki İngilizce örnekler, belirtilen kaynak sayfalardan alınan cümleler veya açıkça belirtilen kısa parçalardır. Satır sonu bölünmeleri giderilmiştir. Formüllerde **S = subject (özne)**, **V = verb (fiil)**, **V1 = yalın fiil**, **V3 = past participle (fiilin üçüncü biçimi)**; **-ing = fiilin -ing biçimi** anlamındadır. Sayfa numaraları PDF sayfalarıyla aynıdır.

## 1. Concession — despite / although / even though

**İşlev:** Beklenen sonucun gerçekleşmediğini, “rağmen” ilişkisini anlatır. Yapıların ardından gelen söz dizimi farklıdır.

> **Formül:**<br/>
> **despite + noun / -ing**<br/>
> **although / even though + S + V**<br/>

> **English — Kaynak örneği (s. 3):** “Despite having a logically modular architecture, the FTGO application is packaged as a single WAR file.”
>
> **Türkçe:** “Mantıksal açıdan modüler bir mimariye sahip olmasına rağmen FTGO uygulaması, tek bir WAR dosyası olarak paketlenir.”

> **English — Kaynak örneği (s. 14):** “Although services in a microservice architecture aren’t always tiny, they’re almost always much smaller.”
>
> **Türkçe:** “Microservice mimarisindeki servisler her zaman çok küçük olmasa da neredeyse her zaman çok daha küçüktür.” Karşılaştırmanın diğer tarafı, önceki cümlelerde anlatılan SOA servisleridir.

> **English — Kaynak parçası (s. 24):** “even though services can be unavailable”
>
> **Türkçe:** “servisler kullanılamaz durumda olabilse bile”

**YDS ipucu:** Boşluktan sonra özne ve çekimli fiil varsa although/even though; isim veya -ing varsa despite düşünün. Even though burada kabul edilen bir olasılığı karşıtlık içinde sunar; even if ile otomatik olarak eşitlemeyin.

> **Common mistake:** “Despite of” kullanılmaz. **Despite the complexity** ve **although the system is complex** doğrudur. “Despite the fact that + S + V” ise mümkündür; that-cümlesini isim grubu olan the fact taşır.

## 2. İki yönü karşılaştırmak — on the one hand / on the other hand / whereas

**İşlev:** Aynı durumun iki farklı yönünü veya iki seçeneği karşılaştırır. Her karşılaştırma tam bir zıtlık olmak zorunda değildir.

> **Formül:** **On the one hand, S + V. On the other hand, S + V.** Ayrıca **S + V, whereas S + V.**

> **English — Kaynak örneği (s. 8):** “On the one hand, a disciplined team can slow down the pace of its descent toward monolithic hell.”
>
> **Türkçe:** “Bir yandan, disiplinli bir ekip monolitik çıkmaza doğru gidiş hızını yavaşlatabilir.”

> **English — Kaynak örneği (s. 8):** “On the other hand, they can’t avoid the issues of a large team working on a single monolithic application.”
>
> **Türkçe:** “Diğer yandan, büyük bir ekibin tek bir monolitik uygulama üzerinde çalışmasından doğan sorunlardan kaçınamazlar.”

> **English — Kaynak örneği (s. 14):** “As a result, a SOA application usually consists of a few large services, whereas a microservices-based application typically consists of dozens or hundreds of smaller services.”
>
> **Türkçe:** “Sonuç olarak, bir SOA uygulaması genellikle birkaç büyük servisten oluşurken microservice tabanlı bir uygulama tipik olarak onlarca veya yüzlerce daha küçük servisten oluşur.”

**YDS ipucu:** İlk iki ifade cümleler arasında düşünce düzenler. Whereas, iki karşılaştırılan cümleciği birbirine bağlar. Whereas'ı zaman bildiren “o sırada” anlamıyla okumayın.

## 3. Relative clauses — that / which / each of which / within which

**İşlev:** Relative clause (ilgi cümleciği), bir ismin hangisi olduğunu belirler veya onun hakkında ek bilgi verir.

> **Formül:** **noun + that/which + V**; **noun, which + V**; **plural noun, each of which + singular V**; **noun + preposition + which + S + V**.

> **English — Kaynak örneği (s. 20):** “A pattern is a reusable solution to a problem that occurs in a particular context.”
>
> **Türkçe:** “Bir örüntü, belirli bir bağlamda ortaya çıkan bir probleme yönelik yeniden kullanılabilir bir çözümdür.” Burada that, problem ismini niteler.

> **English — Kaynak örneği (s. 3):** “The business logic consists of modules, each of which is a collection of domain objects.”
>
> **Türkçe:** “İş mantığı, her biri bir domain object koleksiyonu olan modüllerden oluşur.” Each tek tek ele aldığı için yüklem **is** olur.

> **English — Kaynak parçası (s. 21):** “the context within which it applies”
>
> **Türkçe:** “uygulandığı bağlam”

**YDS ipucu:** Önce nitelenen ismi bulun. Within which ifadesindeki edat, apply fiilinin bağlamla ilişkisini taşır. Virgüllü ek bilgi cümleciğinde which yerine that kullanmayın.

> **Common mistake:** “Each of which **are**” yerine “each of which **is**” gerekir. Yakındaki çoğul modules sözcüğü, each'in tekil oluşunu değiştirmez.

## 4. Reduced relative clauses — written / built / described

**İşlev:** Edilgen ilgi cümleciği bazen relative pronoun + be çıkarılarak kısalır. İsimden sonra gelen V3, “... yapılan/yazılan” anlamı verebilir.

> **Formül:** **noun + which/that + be + V3 → noun + V3**.

> **English — Kaynak örneği (s. 7):** “Quite often, they must maintain an application written using an increasingly obsolete technology stack.”
>
> **Türkçe:** “Çoğu zaman, giderek eskimekte olan bir teknoloji yığını kullanılarak yazılmış bir uygulamanın bakımını yapmak zorundadırlar.”

**Çözümleme:** “An application **written** using...” → “an application **that was written** using...” biçiminde açılabilir. Written uygulamayı niteler; cümlenin çekimli ana fiili **must maintain**'dir. Kısaltılmış biçim tek başına zamanı bütünüyle belirtmez; açılım bağlama göre seçilir.

> **English — Kaynak örneği (s. 14):** “Applications built using the microservice architecture tend to use lightweight, open source technologies.”
>
> **Türkçe:** “Microservice mimarisi kullanılarak oluşturulan uygulamalar, hafif ve açık kaynak teknolojiler kullanma eğilimindedir.”

**YDS ipucu:** Bir ismin ardından V3 gördüğünüzde hemen ikinci bağımsız yüklem aramayın. Önce “that is/was ...” şeklinde bir ilgi cümleciği kurulup kurulamadığını kontrol edin.

## 5. Passive voice ve modal passive

**İşlev:** Passive voice (edilgen çatı), işi yapan kişiden çok işlem gören şeyi öne çıkarır. Teknik kaynaklarda uygulamalar, veriler ve servisler sıkça özne olur.

> **Formül:** **S + be + V3**; **S + modal + be + V3**; tamamlanmış sonuç için **S + have/has + been + V3**.

> **English — Kaynak örneği (s. 11):** “Applications must be decomposed into modules that are developed and understood by different people.”
>
> **Türkçe:** “Uygulamalar, farklı kişilerce geliştirilen ve anlaşılan modüllere ayrılmalıdır.”

**Çözümleme:** **Must be decomposed** zorunluluk bildiren edilgen yapıdır. **Are developed and understood** ise modules ismini açıklayan iki edilgen eylemdir. By different people, işi yapanları belirtir.

> **English — Kaynak örneği (s. 28):** “In a microservice architecture, users are typically authenticated by the API gateway.”
>
> **Türkçe:** “Microservice mimarisinde kullanıcıların kimliği genellikle API gateway tarafından doğrulanır.”

**YDS ipucu:** Must/can/should'dan sonra yalın fiil gelir; edilgen gerekiyorsa bu fiil **be** olur. Must decomposed veya must been decomposed yazılmaz.

> **Memory tip:** **Service deploys X** = servis X'i dağıtır. **Service is deployed** = servis dağıtılır. Öznenin işi yapıp yapmadığını sorarak active/passive ayrımını bulun.

## 6. Conditionals — gerçek koşul ve varsayımsal koşul

**İşlev:** If, bir sonuç için koşul kurar. Zaman biçimi ve bağlam, koşulun gerçek bir olasılık mı yoksa varsayım mı olduğunu gösterir.

> **Formül:**<br/>
> Gerçek gelecek olasılığı: **If + present simple, will + V1**<br/>
> Varsayımsal şimdiki/gelecek durum: **If + past simple, would + V1**<br/>

> **English — Kaynak örneği (s. 19):** “If you pick the microservice architecture, you’ll need to address lots of issues.”
>
> **Türkçe:** “Microservice mimarisini seçerseniz birçok konuyu ele almanız gerekecek.”

> **English — Kaynak örneği (s. 4):** “If the FTGO application were written in the Go language (GoLang), it would be a single executable.”
>
> **Türkçe:** “FTGO uygulaması Go dilinde yazılmış olsaydı, tek bir çalıştırılabilir dosya olurdu.” Burada geçmişte gerçekleşmiş bir olay anlatılmıyor; mevcut Java uygulamasına alternatif bir durum düşünülüyor.

**YDS ipucu:** İkinci örnekte **were written**, varsayımsal koşulun edilgen biçimidir. “Geçmişe aykırı koşul” formülü olan **if + had been written / would have been** ile karıştırmayın. Türkçedeki “olsaydı” tek başına hangi İngilizce conditional'ın seçileceğini belirlemez.

## 7. too ... to ... — sınırı aşan derece

**İşlev:** Bir niteliğin, eylemin yapılmasını engelleyecek ölçüde fazla olduğunu belirtir.

> **Formül:** **too + adjective + to + V1**; edilgen eylemle **too + adjective + to be + V3**.

> **English — Kaynak örneği (s. 11):** “A modern application like FTGO is too large to be developed by an individual.”
>
> **Türkçe:** “FTGO gibi modern bir uygulama, tek bir kişinin geliştiremeyeceği kadar büyüktür.”

> **English — Kaynak örneği (s. 11):** “It’s also too complex to be understood by a single person.”
>
> **Türkçe:** “Ayrıca tek bir kişinin anlayamayacağı kadar karmaşıktır.”

**YDS ipucu:** Buradaki too, “çok”tan fazlasını söyler: sonuçta bir sınır aşılır. **Very complex** yalnızca derece bildirir; **too complex to understand** anlamına otomatik olarak gelmez.

> **Common mistake:** “To be developed” edilgendir. Uygulama bir şey geliştirmiyor; uygulamanın kendisi geliştiriliyor.

## 8. Inversion — cümle başında not only

**İşlev:** Not only, cümle başına taşındığında vurgulanan ilk cümlecikte yardımcı fiil öznenin önüne gelir. Buna inversion (devrik dizilim) denir.

> **Formül:** **Not only + auxiliary + S + V, ... also ...**. Past simple'da yardımcı yoksa **did + S + V1** kullanılır.

> **English — Kaynak örneği (s. 4):** “Not only did this increase the growth rate of the code base, it also increased the management overhead.”
>
> **Türkçe:** “Bu durum yalnızca kod tabanının büyüme hızını artırmakla kalmadı, yönetim yükünü de artırdı.”

**Çözümleme:** Normal sıra **this increased** iken vurgulu sıra **not only did this increase** olur. İkinci cümlecik normal sıradadır: **it also increased**. Kaynakta but yoktur; yaygın bir başka kurulum **not only ... but also ...** biçimindedir.

**YDS ipucu:** Did, geçmiş zaman bilgisini taşıdığı için ardından **increase** gelir; increased gelmez. Not only cümlenin ortasında yalnızca iki ismi veya sıfatı bağlıyorsa bu devriklik otomatik olarak oluşmaz.

## 9. Present perfect — geçmişten bugüne biriken durum

**İşlev:** Geçmişte başlayan veya gerçekleşen durumun konuşulan şimdiyle bağlantısını kurar. Since, başlangıç noktasını belirtir.

> **Formül:** **S + have/has + V3**; **since + başlangıç noktası**.

> **English — Kaynak örneği (s. 20):** “Since the mid-1990s, software developers have documented numerous software patterns.”
>
> **Türkçe:** “1990'ların ortalarından bu yana yazılım geliştiriciler çok sayıda yazılım örüntüsünü belgelemiştir.”

**Çözümleme:** Başlangıç mid-1990s; birikim anlatıcının konuştuğu zamana kadar uzanır. Numerous software patterns nesnesidir; documented, have ile perfect yapı kurar.

> **English — Kaynak örneği (s. 2):** “Over the years, it has become a large, complex application.”
>
> **Türkçe:** “Yıllar içinde büyük ve karmaşık bir uygulamaya dönüşmüştür.”

**YDS ipucu:** **Since 2005** başlangıç; **for several years** süre belirtir. Since tek başına her zaman present perfect zorunlu kılmaz; anlatının referans zamanı geçmişteyse past perfect kullanılabilir. Sonraki başlığa bakın.

## 10. Past perfect — geçmişteki bir noktadan daha öncesi

**İşlev:** Geçmişte anlatılan ana olaydan önce gerçekleşmiş durumu işaretler.

> **Formül:** **S + had + V3**.

> **English — Kaynak örneği (s. 1):** “Her day had started off really well.”
>
> **Türkçe:** “Günü gerçekten çok iyi başlamıştı.”

**Bağlam:** Hikâyenin ana sahnesi pazartesi öğle vaktidir. Günün başlangıcı bu geçmiş sahneden daha öncedir; had started bu sıralamayı kurar.

> **English — Kaynak örneği (s. 2):** “Since its launch in late 2005, FTGO had grown by leaps and bounds.”
>
> **Türkçe:** “FTGO, 2005'in sonlarında faaliyete geçmesinden bu yana çok hızlı büyümüştü.”

**YDS ipucu:** Burada since olmasına rağmen had grown seçilmiştir; bakış noktası anlatıdaki geçmiş zamandır. **Have/has** ile **had** seçimini yalnızca zaman zarfına bakarak yapmayın; olayların referans noktasını bulun.

> **Memory tip:** **Have documented** geçmişten anlatıcının şimdisine bakar. **Had started** geçmişteki sahneden daha geriye bakar.

## 11. Result participle — virgülden sonra making ...

**İşlev:** Ana cümlenin sonucunu, -ing ile başlayan ek bir yapı üzerinden anlatır. Her -ing yapısı “-erek” diye çevrilmez.

> **Formül:** **S + V, -ing ...**; sonuç yapısı olarak **..., making + object + adjective**.

> **English — Kaynak örneği (s. 15):** “The small code base doesn’t slow down the IDE, making developers more productive.”
>
> **Türkçe:** “Küçük kod tabanı IDE'yi yavaşlatmaz; bu da geliştiricileri daha üretken kılar.”

**Çözümleme:** Making, ayrı bir öznesi olan çekimli fiil değildir. Önceki durumun sonucu **developers more productive** şeklinde açıklanır. Anlamı **and this makes developers more productive** biçiminde açılabilir.

> **English — Kaynak parçası (s. 2):** “making it next to impossible to meet the business’s goals”
>
> **Türkçe:** “işletmenin hedeflerine ulaşmayı neredeyse imkânsız hâle getirerek”

**YDS ipucu:** Virgülden sonraki -ing'in nitelenen bir isme mi, aynı öznenin eylemine mi, yoksa bütün önceki duruma mı bağlandığını kontrol edin. Burada doğal Türkçe için “bu da...” kullanılabilir.

## 12. While / when + -ing — eşzamanlılık ve bağlam

**İşlev:** Bir eylem sürerken diğerinin gerçekleşmesini veya genel eylem bağlamını anlatır. Özne, bağlamdan anlaşılabiliyorsa kısa biçim kullanılır.

> **Formül:** **while / when + -ing**; bağlama göre **while + S + be + -ing** veya **when + S + V** olarak açılabilir.

> **English — Kaynak örneği (s. 2):** “It was unclear to Mary how she could fight today’s fires while simultaneously improving the way software was developed at FTGO.”
>
> **Türkçe:** “Mary, FTGO'da yazılım geliştirme biçimini aynı anda iyileştirirken günlük acil sorunlarla nasıl başa çıkabileceğini bilmiyordu.”

**Çözümleme:** **While simultaneously improving** bölümünde anlaşılan özne she, yani Mary'dir. “Fight fires” burada gerçek yangın söndürmek değil, acil sorunlarla uğraşmaktır.

> **English — Kaynak parçası (s. 11):** “when developing large, complex applications”
>
> **Türkçe:** “büyük ve karmaşık uygulamalar geliştirirken”

**YDS ipucu:** While her zaman karşıtlık kurmaz. Burada simultaneously sözcüğü aynı anda yapılan iki işi açıkça işaretler. Kısaltılmış yapının öznesini doğru eyleme bağlayın.

## 13. Purpose — so that / in order to

**İşlev:** Bir eylemin amacını anlatır. So that yeni bir cümlecik açabildiği için iki bölümün öznesi farklı olabilir.

> **Formül:** **S + V + so that + S + V**; **in order to + V1**; özne açıkça belirtilecekse **in order for + noun + to + V1**.

> **English — Kaynak parçası (s. 30):** “design your organization so that its structure mirrors your microservice architecture”
>
> **Türkçe:** “organizasyonunuzu, yapısı microservice mimarinizi yansıtacak şekilde tasarlayın”

**Çözümleme:** Tasarlayan kişi “you”dur; yansıtma eyleminin öznesi “its structure”dır. So that böylece farklı özneye geçiş sağlar.

> **English — Kaynak örneği (s. 32):** “In order for FTGO to successfully accomplish this, however, it must take into account the transition model and consider people’s emotions.”
>
> **Türkçe:** “Ancak FTGO'nun bunu başarıyla gerçekleştirebilmesi için geçiş modelini hesaba katması ve insanların duygularını dikkate alması gerekir.”

**YDS ipucu:** **So that** amaç cümleciğidir; **so + adjective + that** ise derece-sonuç yapısıdır. Araya sıfat girip girmediğine dikkat edin.

## 14. Embedded questions — whether ve soru biçimindeki yan cümleler

**İşlev:** Bir soruyu, kararın veya belirsizliğin içeriği olarak cümleye yerleştirir. Whether, “olup olmadığı / yapıp yapmama” anlamı verir.

> **Formül:** **decide whether + S + V**; **decide whether to + V1**; **Whether + S + V + ana yüklem**.

> **English — Kaynak örneği (s. 19):** “Whether this architecture is appropriate for your application depends on many factors.”
>
> **Türkçe:** “Bu mimarinin uygulamanıza uygun olup olmadığı, birçok etkene bağlıdır.”

**Çözümleme:** Bütün **Whether this architecture is appropriate for your application** bölümü ana cümlenin öznesidir. Ana yüklem **depends**'tir. İç dizilim **this architecture is** olarak kalır; soru dizilimindeki **is this architecture** kullanılmaz.

> **English — Kaynak örneği (s. 23):** “The pattern language first helps you decide whether to use the microservice architecture.”
>
> **Türkçe:** “Örüntü dili, önce microservice mimarisini kullanıp kullanmamaya karar vermenize yardımcı olur.”

**YDS ipucu:** **Whether to use** doğrudur; bu infinitive yapısında **if to use** kullanılamaz. Whether, görünür bir or not olmasa da iki olasılığı anlatabilir.

## 15. Method — by + -ing

**İşlev:** Bir sonuca hangi yöntemle ulaşıldığını açıklar: “... yaparak”.

> **Formül:** **S + V + by + -ing**.

> **English — Kaynak örneği (s. 30):** “You grow the organization by adding teams.”
>
> **Türkçe:** “Yeni ekipler ekleyerek organizasyonu büyütürsünüz.”

**Çözümleme:** Büyütme eyleminin yöntemi **adding teams**'tir. By bir edattır; ardından bu kullanımda yalın fiil değil -ing gelir.

> **English — Kaynak örneği (s. 20):** “A software pattern solves a software architecture or design problem by defining a set of collaborating software elements.”
>
> **Türkçe:** “Bir yazılım örüntüsü, işbirliği yapan yazılım öğeleri kümesini tanımlayarak bir yazılım mimarisi veya tasarım problemini çözer.”

**YDS ipucu:** **By defining** yöntemi; **to define** çoğu bağlamda amacı anlatır. İkisini yalnızca Türkçede benzer duyuldukları için değiştirmeyin. By developers ise edilgen cümlede eylemi yapanları gösterebilir.

## 16. Yerine koyma ve dışlama — instead of / without + -ing

**İşlev:** Instead of, tercih edilmeyen eylemin yerine başka bir eylemi koyar. Without, eşlik etmeyen veya yapılmayan eylemi belirtir.

> **Formül:** **instead of + noun / -ing**; **without + noun / -ing**.

> **English — Kaynak örneği (s. 15):** “Employee satisfaction is higher because more time is spent delivering valuable features instead of fighting fires.”
>
> **Türkçe:** “Acil sorunlarla uğraşmak yerine değerli özellikler sunmaya daha fazla zaman ayrıldığı için çalışan memnuniyeti daha yüksektir.”

> **English — Kaynak örneği (s. 30):** “Each team can develop, deploy, and scale their services without coordinating with other teams.”
>
> **Türkçe:** “Her ekip, diğer ekiplerle koordinasyon kurmadan kendi servislerini geliştirebilir, dağıtabilir ve ölçekleyebilir.”

**YDS ipucu:** Without tek başına “yerine” demek değildir. İkinci örnekte koordinasyonun yerine yeni bir eylem seçilmiyor; belirtilen eylemler onun yokluğunda yapılıyor. Teknik iddia, kaynağın bağımsız ekip bağlamında okunmalıdır.

> **Common mistake:** **Instead of to fight** veya **without to coordinate** yazılmaz. Bu edatlardan sonra **fighting / coordinating** kullanılır.

## 17. Comparisons — much more / that of / as ... as

**İşlev:** Nicelik veya niteliği karşılaştırır. That of, aynı ismi tekrar etmeden karşılaştırma yapmayı sağlar.

> **Formül:** **much + comparative**; **A is higher than that of B**; **as + adjective/adverb + as**.

> **English — Kaynak örneği (s. 30):** “The velocity of the team of teams is significantly higher than that of a single large team.”
>
> **Türkçe:** “Ekiplerden oluşan yapının hızı, tek bir büyük ekibin hızından belirgin biçimde yüksektir.”

**Çözümleme:** **That**, velocity yerine kullanılır. Karşılaştırılan şey “hız” ile “ekip” değil, iki yapının hızıdır. Significantly, higher karşılaştırmasını güçlendirir.

> **English — Kaynak örneği (s. 30):** “By doing so, you ensure that your development teams are as loosely coupled as the services.”
>
> **Türkçe:** “Bunu yaparak geliştirme ekiplerinizin de servisler kadar gevşek bağlı olmasını sağlarsınız.”

**YDS ipucu:** Karşılaştırmayı **much more scalable**, **far fewer outages** gibi ifadeler güçlendirebilir; **very more scalable** kullanılmaz. As ... as yapısında comparative biçim kullanılmaz.

## 18. Causative structures — make / enable / allow

**İşlev:** Bir durumun başka bir kişiye eylem yaptırmasını veya o eylemi mümkün kılmasını anlatır. Fiilden sonraki yapı seçilen fiile göre değişir.

> **Formül:**<br/>
> **make + object + V1** — bir eyleme neden olmak<br/>
> **make + object + adjective** — bir duruma getirmek<br/>
> **enable / allow + object + to + V1** — olanak sağlamak / izin vermek<br/>

> **English — Kaynak örneği (s. 2):** “The conference had made Mary realize that FTGO was suffering from a case of monolithic hell and that the cure was to adopt the microservice architecture.”
>
> **Türkçe:** “Konferans, Mary'nin FTGO'nun monolitik çıkmaz yaşadığını ve çözümün microservice mimarisini benimsemek olduğunu fark etmesini sağlamıştı.”

**Çözümleme:** **Had made** past perfect; **Mary** nesne; **realize** yalın fiildir. Realize'dan sonra to kullanılmaz.

> **English — Kaynak parçası (s. 3):** “which enable the business logic to access the MySQL database and invoke cloud services such as Twilio and Stripe”
>
> **Türkçe:** “iş mantığının MySQL veritabanına erişmesini ve Twilio ile Stripe gibi bulut servislerini çağırmasını sağlayan”

**Çözümleme:** **Enable + the business logic + to access** yapısı vardır. And ile bağlanan ikinci fiil invoke, aynı to kapsamındadır.

**YDS ipucu:** **Make someone do**, fakat **enable someone to do**. Make + sıfat kullanımı için “making developers more productive” örneğine, [11. başlığa](#11-result-participle--virgülden-sonra-making-) dönün.

## Mini quiz — Özgün çalışma soruları

Aşağıdaki sorular gerçek sınav sorusu değildir. Her sorunun **tek doğru cevabı** vardır; verilen bağlamı koruyun.

1. ______ having a modular structure, the application is deployed as one unit. A) Although B) Despite C) Because
2. Not only did the change ______ the code base larger, it also increased overhead. A) made B) making C) make
3. Applications must ______ into modules. A) decomposed B) be decomposed C) been decomposed
4. Since the mid-1990s, developers ______ many patterns. Birikim anlatıcının şimdisine kadar sürüyor. A) have documented B) had documented C) will document
5. The application is too complex ______ by one person. A) understand B) understanding C) to be understood
6. If you choose this architecture, you ______ additional issues. Gelecekteki gerçek bir olasılık anlatılıyor. A) will face B) would have faced C) had faced
7. The pattern helps us decide ______ to use the architecture. A) if B) whether C) that
8. We grow the organization by ______ teams. A) add B) to add C) adding
9. The team delivers features instead of ______ fires. A) fighting B) to fight C) fought
10. The framework enables the service ______ requests. A) handle B) to handle C) handled
11. The system consists of modules, each of which ______ a clear responsibility. A) have B) has C) having
12. “The velocity of this team is higher than that of the other team.” cümlesindeki **that** neyin yerine kullanılır? A) team B) velocity C) other

## Cevaplar ve açıklamalar

1. **B — Despite.** Ardından -ing gelir. Although özne ve çekimli fiil ister; because burada hem söz dizimine hem karşıtlık anlamına uymaz.
2. **C — make.** Did zaten geçmiş zamanı taşır. Made ikinci kez geçmiş işaretler; making bu yapıda kullanılamaz.
3. **B — be decomposed.** Modal passive: must + be + V3. A'da be eksiktir; C'deki been modal'ın hemen ardından gelemez.
4. **A — have documented.** Referans noktası şimdidir. B daha sonraki bir geçmiş noktasından geriye bakmayı, C geleceği anlatır.
5. **C — to be understood.** Too ... to yapısı ve edilgen anlam birlikte gerekir. A ve B bu yapıyı kurmaz.
6. **A — will face.** If + present, will + V1. Diğer seçenekler verilen zaman ilişkisini karşılamaz.
7. **B — whether.** Whether to + V1 mümkündür. If to ve that to bu görevde kullanılamaz.
8. **C — adding.** By edatından sonra -ing gerekir; A ve B bu formüle uymaz.
9. **A — fighting.** Instead of + -ing. B infinitive, C geçmiş biçimdir; ikisi de burada yanlış yapıdır.
10. **B — to handle.** Enable + nesne + to + V1. A, make ile görülen yapıyla karıştırılmıştır; C bu fiil tamlamasını kurmaz.
11. **B — has.** Each tekildir. A çoğuldur; C çekimli yüklem değildir.
12. **B — velocity.** Karşılaştırılan iki ekibin hızıdır. A ve C karşılaştırmanın isim tekrarını doğru çözmez.

## Kısa tekrar haritası

| Okurken görülen işaret | Sorulacak soru | Örnek yapı |
| --- | --- | --- |
| despite / although | Karşıtlıktan sonra isim mi cümlecik mi geliyor? | despite + -ing |
| which / written | Hangi isim açıklanıyor? | application written using ... |
| must be / can be | Özne işi yapıyor mu, işlem mi görüyor? | must be decomposed |
| if / would | Gerçek olasılık mı, varsayım mı? | if ... were ..., would ... |
| have / had + V3 | Referans zamanı şimdi mi, geçmiş mi? | have documented / had started |
| virgül + making | Önceki durumun sonucu mu açıklanıyor? | ..., making developers ... |
| so that / by | Amaç mı, yöntem mi anlatılıyor? | so that it ... / by adding ... |
| whether | Kararın konusu “olup olmadığı” mı? | whether to use ... |
| that of | Hangi isim tekrarlanmadan karşılaştırılıyor? | higher than that of ... |
| enable / make | Nesneden sonra to gerekiyor mu? | enable X to do / make X do |
